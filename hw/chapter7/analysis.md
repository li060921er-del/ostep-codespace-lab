# Chapter 7: Scheduling Analysis

## 实验一：FIFO 策略

**作业参数：** `-l 100,200,300 -p FIFO`

### 阶段 1：预测
假设三个作业同时到达（时间 0）：
1. Job 0 (length=100)：在时间 0 开始，时间 100 完成。周转时间 = 100 - 0 = 100
2. Job 1 (length=200)：在时间 100 开始，时间 300 完成。周转时间 = 300 - 0 = 300
3. Job 2 (length=300)：在时间 300 开始，时间 600 完成。周转时间 = 600 - 0 = 600
**预测的平均周转时间** = (100 + 300 + 600) / 3 = 333.33

### 阶段 2：验证
运行 `... -p FIFO -c` 后，终端显示的实际结果为：
- 实际平均周转时间 = 333.33 
- 实际平均响应时间 = 133.33
- 实际平均等待时间 = 133.33
### 结论与分析
我的预测与模拟器结果一致，说明对FIFO理解正确。FIFO会导致长作业后面的短作业等待时间非常长，产生“护航效应（Convoy Effect）”。

## 实验二：SJF 策略

**作业参数：** `-l 300,100,200 -p SJF`

### 阶段 1：预测
作业到达顺序是 300, 100, 200，由于 SJF 是非抢占式的，它会先挑选最短的作业执行。
调度顺序会被重排为：100 -> 200 -> 300。
1. Job 100：在时间 0 开始，时间 100 完成。周转时间 = 100
2. Job 200：在时间 100 开始，时间 300 完成。周转时间 = 300
3. Job 300：在时间 300 开始，时间 600 完成。周转时间 = 600
**预测的平均周转时间** = (100 + 300 + 600) / 3 = 333.33

### 阶段 2：验证
运行带 `-c` 的命令验证结果：
- 实际平均周转时间 = 333.33
- 实际平均响应时间 = 133.33
- 实际平均等待时间 = 133.33

### 结论与分析
**SJF 通过重排作业顺序，让短作业优先执行，从而优化了平均周转时间。**
（对比：如果使用 FIFO 执行 300,100,200，长作业 300 会阻塞后面的短作业，导致平均周转时间高达 466.67，这就是护航效应。SJF 解决了这个问题。）
